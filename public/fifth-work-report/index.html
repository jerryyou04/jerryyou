Abstract / Introduction

For my fifth co-op term, I continued working as a Software Engineer Intern at TD Bank. This was the second half of my eight-month placement with the Enterprise Governance, Risk, and Compliance team.

My work focused on improving the team's ServiceNow development process. I built Python tools for exporting scripts into GitHub, wrote Jest tests for existing business logic, automated an access-control workflow, and created data pipelines for Power BI reporting.

Since I already knew the team and the system from my fourth term, I was able to work more independently and take on projects that affected the team's regular development and support work.

About the Employer

TD Bank is one of Canada's largest financial institutions, with operations across banking, investing, insurance, and internal technology systems. I continued working from TD Terrace in Toronto with the same managers and team as my fourth work term.

My team worked on internal Enterprise Governance, Risk, and Compliance software. The systems support governance workflows, access control, system changes, and internal reporting. This report leaves out confidential implementation details and focuses on the work and skills I developed.

Learning Goals

Goal 1 - Critical & Creative Thinking: Problem Solving

Goal: Build a structured approach to debugging and root cause analysis in enterprise software environments.

Action plan: Apply systematic debugging methods when investigating script failures; log findings and solutions for reference.

Measure of success: Reduce time-to-resolution on recurring issues by maintaining a personal knowledge base of fixes by the end of the term.

Reflection: I became more systematic when debugging. Instead of reading through a script and guessing, I tried to reproduce the issue, isolate the relevant logic, and verify the fix with a test. Exporting the ServiceNow scripts into GitHub made the code searchable in VS Code and gave me version history to compare. The Jest tests also gave me a record of past issues and expected behaviour. I did not formally measure the time saved on every issue, but recurring problems became easier to trace and check.

Goal 2 - Communicating: Oral Communication

Goal: Develop the ability to clearly communicate technical findings to non-technical stakeholders.

Action plan: Document code review findings in plain language and present updates during team check-ins.

Measure of success: Receive positive feedback from a supervisor on at least one written report or presentation delivered during the term.

Reflection: I practised explaining my work in terms of the problem and result instead of only describing the code. For example, I explained the access-control automation by focusing on the manual work it removed, and I described the dashboards by the information they made available. I also explained the benefits of Git versioning, code search, and automated tests when introducing the new development workflow. Its adoption across the team showed me that the purpose and value of the tool were understood.

Goal 3 - Literacy: Technological Literacy

Goal: Strengthen proficiency in JavaScript and ServiceNow development through hands-on GRC scripting work.

Action plan: Write and review business rules, script includes, and scheduled jobs; seek feedback from senior developers.

Measure of success: Successfully identify and resolve at least three bugs in production scripts with documented fixes.

Reflection: I spent the term working directly with ServiceNow scripts and their JavaScript business logic. Writing Jest tests required me to understand the code, its ServiceNow dependencies, and the edge cases it needed to handle. I also used that knowledge when building the access-control workflow. Code review and feedback from more experienced developers helped me make my changes safer and easier to maintain. By the end of the term, I was much more comfortable reading, testing, debugging, and changing ServiceNow code.

Job Description

My work covered developer tooling, testing, workflow automation, and reporting.

ServiceNow Script Export and Git Workflow

I developed Python tooling to export ServiceNow scripts and organize them in GitHub. This allowed the team to work with the scripts in VS Code, search across the codebase, review Git history, and use GitHub Copilot. The workflow was adopted by the team and made the scripts easier to find and review.

Jest Testing

I added Jest test suites for selected ServiceNow business logic. The tests reached more than 80% coverage in the targeted areas and provided a repeatable way to check behaviour after code changes.

Access-Control Workflow Automation

Organizational changes and group renames required access-control relationships to be relinked. I implemented a ServiceNow workflow that automated this process and eliminated about two weeks of manual work.

Data Pipelines and Reporting

I implemented Python ETL pipelines that moved data from ServiceNow into Microsoft SQL Server. The data was used in Power BI dashboards for deployments, developer activity, and system changes.

Key Technologies

  • Development: Python, JavaScript, ServiceNow, VS Code.
  • Testing and version control: Jest, Git, GitHub, GitHub Copilot.
  • Data and reporting: Microsoft SQL Server, Power BI.

Overall Reflection

Staying with the same team for a second term let me contribute differently. During my fourth term, I spent more time learning how the platform and existing code worked. This term, I could use that knowledge to improve the development process itself.

The Git workflow was a good example. Writing the exporter was only part of the work. The scripts also needed to be organized in a way that made sense to other developers. Seeing the team use VS Code, Git history, search, tests, and Copilot with the exported code showed me that internal tools need to be useful and easy to adopt.

The access-control workflow showed me the value of understanding a manual process before automating it. The ETL work also gave me more experience following data across ServiceNow, SQL Server, and Power BI. Overall, I became more independent and more comfortable working across different parts of an enterprise system.

Conclusion

During my fifth co-op term, I improved my skills in Python, JavaScript, ServiceNow, Jest, Git, SQL Server, and Power BI. I also improved at debugging existing systems, explaining technical work, and building tools that other developers could use.

The term gave me a better understanding of the work around software development: testing, version control, automation, data movement, and reporting. These are areas I expect to keep using in future software engineering roles.
